Try designs from your agent: the UISandbox MCP server

Say "let me try some designs" to your agent. It opens your running app in UISandbox in your own browser, waits while you pick a look and turn the knobs, and gets back what you turned with a patch for your source. It shows you the patch before it changes a file.

uisandbox-mcp on npmSetup for every client

Add it once

Claude Code:

claude mcp add uisandbox -- npx -y uisandbox-mcp@latest

Or as a Claude Code plugin, the skill and the server in one: /plugin marketplace add Ideelab/uisandbox, then /plugin install uisandbox@uisandbox. Any other MCP client (Cursor, Codex, Claude Desktop) runs npx -y uisandbox-mcp@latest over stdio. It is listed on the MCP registry.

The tools

ToolWhat it does
try_designsFinds the app you are running and opens it live in your browser. No arguments.
wait_for_sendReturns when you press Send to your agent: what you turned, and the patch.
load, openLoad a build, a zip or a dev server, and open the real sandbox with it.
set, state, screensTurn knobs from the agent, read where they stand, list the screens.
exportA patch, CSS or JSON tokens, Tailwind, shadcn, Swift or Android.
verify, screenshotThe 1:1 check and a render, in headless Chromium.

Without the MCP server

An agent with only a shell runs the same thing and gets control back at once:

npx uisandbox-mcp@latest open --detach

It finds the dev server, opens the sandbox in your own browser and returns. Your agent's built-in browser cannot reach your localhost, so the sandbox opens in yours.

Questions

Does it send my code anywhere?

No. The server runs on your machine and serves the sandbox from 127.0.0.1. Nothing is uploaded, and there are no analytics.

Does the agent change my files on its own?

No. After you press Send, the agent gets the patch with your own file names and shows it to you first. The skill tells it to change files only when you say yes.
